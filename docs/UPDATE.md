# AdDroid を更新する (既存ユーザー向け)

新しいバージョンの AdDroid を取り込むときの手順です。**3 ステップ**で終わります。
データベースのスキーマ変更(新しいカラムやテーブルの追加)も `addroid update` が自動で反映します。

> はじめてセットアップする場合は [`SETUP.md`](SETUP.md) を見てください。このページは
> 「すでに動かしている AdDroid を新しいバージョンに上げる」ためのものです。

---

## いちばん簡単な手順

ターミナルで AdDroid のフォルダに移動して、次の 3 つを順番に実行します。

```bash
git pull         # 1. 新しいコードを取り込む
addroid update   # 2. 依存更新 + CLI 再ビルド + クライアント再生成 + DB スキーマ反映 + 健全性チェック
```

最後に、サービスを再起動して反映します。

```bash
addroid start
```

これだけです。`update` は以下を自動で行います。

1. **依存関係の更新** (`npm install`) — `git pull` で増減した依存を取り込む
2. **CLI の再ビルド** — `addroid` コマンド自体を新しいコードに追従させる(新コマンド・新挙動が反映される)
3. **Prisma クライアントの再生成** — 新しいテーブル/カラムにコードを追従させる
4. **DB スキーマの反映** (`prisma db push`) — 不足しているカラム/テーブルを追加する
5. **健全性チェック** — DB 接続とスキーマ整合性を確認し、問題があれば指摘する

> **初回のみ:** `addroid update` をまだ持っていないバージョンから上げる場合は、最初の 1 回だけ
> `npm run addroid -- update` を実行してください(リポジトリのソースを直接実行するため確実です)。
> この update が依存更新と CLI 再ビルドまで行うので、**以降は `git pull` → `addroid update`** の
> 2 手だけで最新化できます。

## 「スキーマが古い」と言われたら

`addroid start` や `addroid doctor` を実行したときに、次のような警告が出ることがあります。

```
[warn ]  schema-drift   DB スキーマがコードより古い可能性があります (未反映の変更あり)。
                        ↳ `addroid update` を実行して DB スキーマを最新化してください。
```

これは「コードは新しいのに、データベースがまだ追いついていない」状態です。
案内のとおり `addroid update` を実行すれば解消します。

## データに影響する変更があった場合

ほとんどの更新は、既存データを保持したまま安全に反映できます(カラムの追加など)。
ただし、まれに既存データに影響しうる変更が含まれることがあります。その場合 `update` は
**自動では適用せず**に停止し、次のように案内します。

```
⚠ このバージョンには既存データに影響しうるスキーマ変更が含まれます。
安全のため自動では適用しませんでした。次の手順で進めてください:

  1) addroid backup           # 念のためバックアップを取得
  2) addroid update --force   # 変更を適用 (data-loss を許可)
```

この場合は、まず **バックアップを取ってから** `--force` を付けて再実行してください。

```bash
npm run addroid -- backup
npm run addroid -- update --force
```

> リリースノート([`CHANGELOG.md`](../CHANGELOG.md))の `### Changed` / `### Removed` に
> **太字**で告知された項目は、破壊的変更の可能性があります。更新前に一度目を通すことをおすすめします。

---

## オプション

| オプション | 説明 |
|-----------|------|
| `--force` | 既存データに影響しうるスキーマ変更も適用する(事前に `addroid backup` 推奨) |
| `--skip-install` | 依存関係の更新 (`npm install`) を省略する(依存が変わっていないと分かっている時) |
| `--skip-checks` | 反映後の健全性チェックを省略する(通常は不要) |

---

## うまくいかないときは

- まず `npm run addroid -- doctor` を実行して、どの項目で問題が出ているか確認してください。
- DB に接続できない場合は、PostgreSQL が起動しているか(`pg_isready`)、`DATABASE_URL` が
  正しいかを確認してください。
- それでも解決しない場合は [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md) を参照してください。
